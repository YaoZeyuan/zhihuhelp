# 前端界面优化方案

本文记录 GUI 下一阶段的界面优化方向。目标不是单纯美化页面，而是让普通用户安装后不用阅读说明，也能完成登录、粘贴知乎链接、生成电子书、打开结果的完整闭环。

## 当前现状

GUI 当前由 `client/src/page/home` 组织，主入口是标签页：

| 页面     | 当前能力                                                     | 主要问题                                                                       |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 任务管理 | 配置任务、排序、图片质量、输出格式、分卷、批量导入、启动任务 | 专家表单感强，默认路径不够突出，普通用户需要理解任务类型、排序、生成模式等概念 |
| 运行日志 | 定时读取 `runtime.log`，支持刷新、清空、打开输出目录         | 只能看原始文本，缺少阶段、进度、失败原因和下一步动作                           |
| 数据浏览 | 展示数据库中回答、文章、想法等数量                           | 只能看汇总数字，无法验证刚才抓到了什么内容                                     |
| 登录     | 通过 webview 登录知乎                                        | 页面偏调试用途，缺少登录状态、登录成功反馈和异常恢复引导                       |
| 调试面板 | 展示调试能力                                                 | 对普通用户暴露过早，容易误触，也会增加理解成本                                 |

## 设计目标

1.  默认路径清晰：普通用户只需要完成“登录 -> 粘贴链接 -> 开始 -> 打开结果”。
2.  状态可见：登录状态、任务合法性、运行阶段、输出结果都要在界面上直接反馈。
3.  高级能力保留但后置：排序、合并、跳过抓取、调试工具等放进高级模式或折叠区域。
4.  错误可恢复：错误提示不仅说明失败，还要告诉用户下一步能做什么。
5.  文案面向用户结果：界面文字优先解释“会得到什么”，避免直接暴露内部实现概念。

## 待改进项

### P0：最小可用闭环

| 编号 | 改进项                 | 说明                                                                                                 | 验收标准                                                            |
| ---- | ---------------------- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| P0-1 | 增加新手默认流程       | 将首页调整为流程式工作台，突出登录、添加内容、输出设置、开始生成、查看结果这几个步骤                 | 新安装用户不看 README，也能跟随界面完成一次电子书生成               |
| P0-2 | 登录状态卡片           | 在首页或顶部展示“已登录 / 未登录 / 登录失效”，提供去登录、重新检测、退出登录动作                     | 未登录时不能直接启动任务；登录成功后界面能即时反馈                  |
| P0-3 | 简化任务输入           | 默认只展示一个“粘贴知乎链接”的输入区，支持单条和多条链接；自动识别任务类型、id，并用列表展示识别结果 | 用户粘贴知乎 URL 后能看到类型、id、是否有效；无效链接有明确错误原因 |
| P0-4 | 默认模式与高级模式分离 | 默认模式隐藏生成模式、排序、跳过抓取、分卷等复杂项，仅保留书名、输出格式、图片质量的常用配置         | 普通用户看到的首屏表单项明显减少；高级用户仍能展开完整配置          |
| P0-5 | 启动前检查             | 点击开始前检查登录状态、任务列表、输出格式、输出目录权限、配置保存结果                               | 检查失败时禁用或中断启动，并给出可执行的修复入口                    |
| P0-6 | 运行状态面板           | 在任务运行时展示当前阶段：初始化、抓取、入库、生成 HTML、生成 EPUB、完成；原始日志放到折叠区         | 用户不用读日志也能知道当前跑到哪一步、是否失败、失败在哪里          |
| P0-7 | 完成页和结果入口       | 任务完成后展示生成结果，提供打开输出目录、打开 HTML、复制输出路径、再次生成等动作                    | 任务完成后用户能从界面直接找到产物，不依赖自动弹出的文件夹          |
| P0-8 | 隐藏调试入口           | 调试面板、打开开发者工具、js-rpc 开发者工具默认隐藏，放入开发者模式                                  | 普通用户主导航中不出现调试页；开发者仍可通过明确入口启用            |

### P1：降低误操作和理解成本

| 编号 | 改进项           | 说明                                                                           | 验收标准                                           |
| ---- | ---------------- | ------------------------------------------------------------------------------ | -------------------------------------------------- |
| P1-1 | 任务识别预览     | 对每条任务展示图标、类型名称、原始链接、解析出的 id、跳过抓取状态              | 用户能在开始前确认任务是否识别正确                 |
| P1-2 | 支持任务模板     | 为常见场景提供模板：导出单个问题、导出用户回答、导出收藏夹、仅从数据库重新生成 | 用户选择模板后只需要填关键 URL                     |
| P1-3 | 更清楚的输出配置 | 将“独立成书 / 按任务合并 / 打乱合并”改为结果导向文案，并配合简短示例           | 用户能理解不同模式会生成几本书、章节如何组织       |
| P1-4 | 日志分级和筛选   | 将日志按信息、警告、错误、成功分类；支持只看错误、复制错误、导出诊断包         | 出错后用户可以快速定位失败原因并反馈问题           |
| P1-5 | 运行中防重复启动 | 任务运行时锁定开始按钮和关键配置项，必要时提示当前任务仍在执行                 | 避免重复点击开始导致并发任务或配置覆盖             |
| P1-6 | 表单布局重组     | 使用固定底部操作区、清晰分区和统一间距；减少横向 Col 表格式布局带来的拥挤感    | 小屏和默认窗口尺寸下，按钮、输入框、提示文案不重叠 |
| P1-7 | 配置持久化与历史 | 展示最近使用任务，可一键重新运行或在上次配置基础上修改                         | 用户不需要每次重新粘贴同一批链接                   |

### P2：增强管理和诊断能力

| 编号 | 改进项       | 说明                                                                       | 验收标准                                       |
| ---- | ------------ | -------------------------------------------------------------------------- | ---------------------------------------------- |
| P2-1 | 数据浏览增强 | 在汇总数字之外，支持浏览作者、问题、文章、想法、收藏夹列表，并查看基础详情 | 用户能确认数据库中有哪些内容，而不只是看到数量 |
| P2-2 | 输出历史管理 | 记录每次生成的书名、时间、任务数量、输出路径和格式                         | 用户能回到历史记录中打开旧产物                 |
| P2-3 | 诊断信息导出 | 一键导出最近配置、运行日志、环境信息、数据库摘要，便于反馈 bug             | 用户反馈问题时不用手动找文件                   |
| P2-4 | 更新检查入口 | 启动时或设置页提示版本状态，并给出下载或查看更新说明入口                   | 用户知道当前版本是否过旧                       |
| P2-5 | 设置页       | 集中管理输出目录、图片质量默认值、开发者模式、日志保留策略等长期配置       | 任务页不再承载所有配置项                       |

## 建议实施顺序

1.  先实现默认流程、登录状态、任务输入简化、启动前检查，保证新手能走通主链路。
2.  再改运行状态和完成页，让任务执行过程可见、结果可达。
3.  然后隐藏调试能力，整理布局和文案，降低普通用户的理解负担。
4.  最后增强数据浏览、历史记录、诊断导出等辅助能力。

## 与后端的协作点

1.  运行状态面板需要后端提供更稳定的结构化日志或阶段事件。当前已有 `runtime.jsonl`，可以优先基于它做解析。
2.  任务预览如果需要展示标题，需要复用或扩展 `get-task-default-title`。
3.  输出历史需要记录任务开始、完成、输出文件路径和格式；可以先在前端本地持久化，后续再整理为统一运行记录。
4.  取消任务、暂停任务不属于当前 P0 范围，除非后端工作流先提供可中断能力。
