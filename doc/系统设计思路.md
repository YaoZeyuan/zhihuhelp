## 核心目标

知乎助手的核心目标是把知乎内容转换为适合个人阅读和整理的本地 HTML/EPUB 电子书。项目不追求复杂商业化能力，优先保证：

1.  输入任务简单。
2.  抓取流程可观察。
3.  本地数据可复用。
4.  输出结果稳定。
5.  新人能快速理解代码结构。

## 当前设计主线

当前项目的业务主线是：

```mermaid
flowchart LR
  A["任务配置"] --> B["抓取知乎数据"]
  B --> C["写入 SQLite"]
  C --> D["生成书籍计划"]
  D --> E["渲染 HTML"]
  E --> F["处理图片和静态资源"]
  F --> G["输出 HTML / EPUB"]
```

项目同时支持 GUI 和命令行入口，但两者最终都复用 Ace 命令体系。GUI 的定位是登录、配置和观察运行状态；命令行的定位是更直接地执行初始化、抓取和生成。

## 下一轮设计方向

下一轮代码规范化改造建议以全链路为目标，把当前互相套用的模块拆成更清晰的层级：

1.  Interface：CLI、Electron、IPC。
2.  Application：初始化、抓取、生成等用例编排。
3.  Domain：任务、内容、排序、分卷、书籍计划。
4.  Infrastructure：知乎请求、SQLite、文件系统、HTML/EPUB 输出。
5.  Shared：配置、日志、队列、错误、公共类型。

改造重点不是“换目录”，而是让每个模块只回答一个问题：

1.  我要执行什么任务？
2.  我要从哪里拿数据？
3.  我要如何保存数据？
4.  我要如何组织成书？
5.  我要如何输出结果？
6.  我要如何记录过程？

详细方案见 [架构规范化改造方案.md](架构规范化改造方案.md)。
