# 问题 9：支持导出 Markdown 格式

## 当前状态

HTML 转 Markdown 在技术上可行，但当前信息尚不足以启动全量开发。需要先确认转换器许可证与 Markdown 产物结构；收到回复并将结论固化为正式需求、清除 TODO 后，才能开始业务代码修改。

## 原始需求

目前已经支持 HTML 格式输出，但用于 AI 分析时，移除布局和样式冗余后的 Markdown 更方便。

根项目已经安装 `pandoc-wasm`，希望评估是否可以通过 Pandoc 转换，在 HTML、EPUB 之外增加 Markdown 输出格式。

## 可行性审阅

- 当前依赖为 `pandoc-wasm@1.1.0`，实际内置 Pandoc 3.10。本地 Node.js 24 环境已经验证 `convert({ from: 'html', to: 'gfm-raw_html', wrap: 'none' }, html, {})` 可以完成转换。
- `gfm-raw_html` 可以生成 GitHub Flavored Markdown，并清理大部分 CSS、布局容器和原始 HTML；转换前仍需移除 HTML 版侧栏目录等纯阅读界面，避免产生无效锚点或冗余文本。
- `pandoc-wasm` 是带顶层 `await` 的纯 ESM 包。当前 Babel 会把动态导入转换成 `require()`，直接接入会触发 ESM/CJS 加载错误。若采用 Pandoc，必须保留 Node.js 原生动态导入，并在懒加载的 Worker Thread 中串行转换，不能阻塞 Electron 主线程。
- 包内 `pandoc.wasm` 约为 58.6 MiB，首次加载还会带来明显的内存开销。它不需要联网加载，但必须验证 Electron 安装包中 WASM 文件的位置和可读性。
- 现有生成链已经在内存中构造单文件 HTML，可以将其作为 Markdown 的转换输入，不需要重新抓取或重新查询业务数据。

## 待确认项

### 1. 转换器与发布许可证

@todo(worker) `pandoc-wasm` 的 npm 包声明为 `GPL-2.0-or-later`，而当前项目、安装包和文档均声明为 MIT；Electron 打包配置还会把生产依赖和 WASM 一起放入安装包。这会增加约 58.6 MiB 的原始资源，并需要明确 GPL 通知、对应源码以及项目整体分发许可安排。以上是工程风险提示，不是法律意见。

请选择一种方案：

1. 保持当前 MIT 分发，移除 `pandoc-wasm`，改用宽松许可证的纯 JavaScript HTML → Markdown 转换器（推荐，安装包更小、内存占用更低）。
2. 继续使用 `pandoc-wasm`，接受安装包和运行内存增长，并在发布前明确处理 GPL 相关分发义务与许可证材料。

@todo(codex) 这是个人的工具类项目，不需要保留源码。所以可以这样做：
> ZhihuHelp 自有源代码采用 MIT OR GPL-2.0-or-later 双重许可；包含 pandoc-wasm/Pandoc 的桌面应用发行版整体按 GPL-2.0-or-later 发布。

这样项目源码本身按mit发布，构建产物基于GPL，可以最大限度降低对使用者的影响

请使用 `@todo(codex)` 回复选择；如果选择 Pandoc，实现将采用懒加载 Worker，未勾选 Markdown 时不会初始化 WASM。

### 2. Markdown 产物与兼容行为

@todo(worker) 请确认是否采用下面的 AI 分析优先方案（推荐）：

- 新增可独立选择的 `markdown` 输出格式，不要求同时勾选 HTML；现有默认值仍为 HTML + EPUB，Markdown 默认不勾选，旧配置行为不变。
- 每个最终分卷或电子书生成一个 UTF-8 GFM 文件：`知乎助手输出的电子书/markdown/<安全书名>.md`。不按回答或文章拆成大量小文件。
- 移除 CSS、HTML 布局容器、侧栏目录和原始 HTML，只保留书本结构、标题、正文、作者等可见元数据、来源链接、列表、引用、代码、表格以及必要的图片信息。
- 图片质量为“无图”时删除图片；其余模式保留图片替代文本和原始远程地址，不额外复制本地图片，以便得到适合单文件上传给 AI 的轻量产物。
- Markdown 转换失败但 HTML 或 EPUB 已成功时，保留可用产物并将本书标记为 `partial_success`；只选择 Markdown 且转换失败时，本书生成失败。
- 最近五日输出历史增加“打开 Markdown”，并与 HTML、EPUB 使用同一安全路径和日志规则。

如果更希望得到可离线搬运的 Markdown 文件夹，请在 `@todo(codex)` 中改选：`markdown/<安全书名>/<安全书名>.md`，同时复制图片到同目录的 `image/`。该方案体积更大，Markdown-only 任务也需要执行图片下载。
