# 问题 8：缓存迁移、单文件 HTML 与任务配置统一

## 已确认需求

1. JSON 导出新增“一键导出全库”，覆盖当前 SQLite 中全部缓存实体和关系表；保留现有按分类和父级筛选导出。
2. JSON 导入为增量导入。新 ID 直接写入；同 ID 优先比较知乎对象 `updated_time`，关系记录比较 `record_at`，只有导入记录更新时才覆盖；时间缺失或相同则保留本地记录。
3. 单文件 HTML 注入完整目录并使用页内锚点。桌面端使用固定、可折叠侧栏，窄屏降级为正文顶部目录。
4. 审计并修复用户、专栏、收藏夹、话题和混合任务等全部信息页；缺失字段不得产生空白信息块。
5. 前后端统一使用共享任务配置 schema，同时保持现有配置文件中 `raw`、`hd` 等序列化值兼容。

## 原始问题

1.  导出json功能有问题，没有导出全部功能。同时需要确认，导入时是否为增量导入，如果有同id数据，应以较新的版本为准
2.  输出的`用户回答`单文件版html中，没有注入index.html这一目录信息。可以在左侧展示目录列表，方便跳转
3.  输出的`用户回答`单文件版html中，用户信息也为空。需要确认下其他类型的信息页是否也有这类问题
4.  如[开发文档](doc\dev\maintenance.md)所述，目前前后端常量存在历史差异，希望一并修复

当前根项目和前端各维护了一套任务常量：

1.  根项目：`src/constant/task_config.ts`
2.  前端：`client/src/resource/const/task_config.ts`

需要特别注意图片质量常量存在历史差异。涉及任务配置转换时，应检查：

1.  `client/src/page/home/component/customer_task/library/task_config_adapter.ts`
2.  `src/domain/task/task_config.ts`
3.  `src/constant/task_config.ts`
4.  `client/src/resource/const/task_config.ts`

后续理想方向是把任务类型、输出格式、图片质量和生成模式整理为单一 schema。

期望前端使用后端的常量定义，以统一为一套代码，并将任务类型、输出格式、图片质量和生成模式整理为单一 schema。
