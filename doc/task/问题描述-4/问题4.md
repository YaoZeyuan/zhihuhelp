# 现有界面判断

当前 GUI 已具备基本可用能力：

1.  任务管理页可以配置任务、批量导入、自动生成书名、设置输出格式、图片质量、排序和分卷，并启动任务。
2.  登录页可以通过知乎 webview 完成登录。
3.  运行日志页可以查看 `runtime.log`，支持自动刷新、手动刷新、清空日志和打开输出目录。
4.  数据浏览页可以查看数据库中的文章、回答、想法等汇总数量。
5.  调试面板和开发者工具入口已经存在，方便开发排查问题。

主要问题是：界面仍偏向开发者和高级用户，主流程没有被突出；普通用户需要理解任务类型、生成模式、排序规则、跳过抓取、日志内容等概念，才能判断下一步该做什么。

# 待改进项

## P0：优先完成，保证小白用户能走通主流程

1.  增加新手默认流程
    1.  将首页调整为流程式工作台，突出“登录 -> 粘贴链接 -> 开始生成 -> 打开结果”。
    2.  默认不要求用户理解任务类型、排序、生成模式等高级概念。
2.  增加登录状态卡片
    1.  在首页或顶部明确展示“已登录 / 未登录 / 登录失效”。
    2.  未登录时启动任务前直接引导到登录页。
    3.  登录成功后提供重新检测和退出登录动作。
3.  简化任务输入
    1.  默认提供一个“粘贴知乎链接”的输入区，支持单条和多条链接。
    2.  自动解析任务类型和任务 id，并展示识别结果。
    3.  无效链接要展示具体原因，不能只显示“未解析到任务id”。
4.  分离默认模式和高级模式
    1.  默认模式只保留书名、输出格式、图片质量等常用配置。
    2.  排序、生成模式、跳过抓取、分卷、备注等配置放入高级模式。
5.  增加启动前检查
    1.  检查登录状态、任务有效性、输出格式、输出目录权限和配置保存结果。
    2.  检查失败时阻止启动，并给出明确的修复动作。
6.  优化运行状态展示
    1.  将原始日志升级为阶段化状态：初始化、抓取、入库、生成 HTML、生成 EPUB、完成。
    2.  普通用户默认看阶段和错误摘要，原始日志放到折叠区域。
7.  增加完成页和结果入口
    1.  任务完成后直接展示生成结果。
    2.  提供打开输出目录、打开 HTML、复制输出路径、重新生成等动作。
8.  隐藏调试入口
    1.  调试面板、开发者工具、js-rpc 开发者工具默认不出现在普通用户主流程中。
    2.  需要时通过开发者模式启用。

## P1：降低误操作和理解成本

1.  增加任务识别预览
    1.  每条任务展示类型、原始链接、解析 id、是否跳过抓取。
    2.  用户可以在开始前确认识别是否正确。
2.  增加常见任务模板
    1.  例如导出单个问题、导出用户回答、导出收藏夹、从数据库重新生成。
    2.  用户选择模板后只填写关键链接。
3.  优化输出配置文案
    1.  将“独立成书 / 按任务合并 / 打乱合并”改成结果导向说明。
    2.  让用户能理解最终会生成几本书、章节如何组织。
4.  增加日志分级和筛选
    1.  将日志区分为信息、警告、错误、成功。
    2.  支持只看错误、复制错误、导出诊断信息。
5.  运行中防重复启动
    1.  任务运行时锁定开始按钮和关键配置项。
    2.  避免重复点击导致任务并发或配置被覆盖。
6.  重组页面布局
    1.  使用更清楚的分区和固定底部操作区。
    2.  减少当前横向表格布局在小窗口下的拥挤感。
7.  增加最近任务
    1.  记录最近使用的任务配置。
    2.  支持一键重新运行或基于上次配置继续修改。

## P2：增强管理和诊断能力

1.  增强数据浏览
    1.  在汇总数量之外，支持浏览作者、问题、文章、想法、收藏夹列表。
    2.  让用户可以确认刚才抓到了哪些内容。
2.  增加输出历史
    1.  记录每次生成的书名、时间、任务数量、输出路径和格式。
    2.  支持从历史记录中打开旧产物。
3.  增加诊断信息导出
    1.  一键导出最近配置、运行日志、环境信息、数据库摘要。
    2.  降低用户反馈 bug 时找文件的成本。
4.  增加更新检查入口
    1.  启动时或设置页展示版本状态。
    2.  当前版本过旧时给出下载或查看更新说明入口。
5.  增加设置页
    1.  集中管理输出目录、默认图片质量、开发者模式、日志保留策略等长期配置。
    2.  避免任务页承载过多低频配置。

# 建议实施顺序

1.  先实现默认流程、登录状态、任务输入简化和启动前检查，保证安装后能顺利跑通第一本电子书。
2.  再实现运行状态面板和完成页，让任务过程和产物位置都清楚可见。
3.  然后整理高级模式、隐藏调试能力、优化页面布局和文案。
4.  最后补充数据浏览、历史记录、诊断导出和设置页。

# 与后端的协作点

1.  运行状态面板最好使用结构化日志或阶段事件。当前项目已有 `runtime.jsonl`，可以优先基于它做解析。
2.  任务预览如果要展示默认标题，可以复用或扩展 `get-task-default-title`。
3.  输出历史需要记录任务开始时间、完成时间、输出路径和输出格式，可以先在前端本地持久化。
4.  暂停任务、取消任务不建议作为当前 P0 目标，除非后端工作流先提供可中断能力。
