# 问题 10：用户标识归一化

## 状态

实现完成，离线全量验收通过。真实 Electron 业务数据不在自动测试中读取或改写，需在更新 `dist` 后由用户按现有任务重跑确认。

## 问题与证据

知乎用户接口同时接受稳定 `id` 和公开 `url_token`。同一用户可以通过
`/people/7eb8dd6d1e665c9b53832a0d8ab3a4c2` 与 `/people/Hentioe` 访问；接口响应和当前数据库记录为：

- `Author.id = 7eb8dd6d1e665c9b53832a0d8ab3a4c2`，是底层稳定身份和 `Author` 主键；
- `Author.url_token = Hentioe`，是可读但可能变化的公开主页标识；
- `Answer.author_id` 使用稳定 `id`，`Answer.author_url_token` 使用响应中的规范 `url_token`。

抓取任务保留了输入的 hash，但生成阶段把该值只当作 `url_token` 查询，导致抓取和持久化全部成功后仍误报“没有可生成的数据”。

## 身份契约

1. 用户任务入口继续接受稳定 `id` 或当前 `url_token`；原始输入保留在任务配置中，不静默改写，以便复现。本期不新增历史 token 的持久化别名表。
2. 模型层统一解析用户身份：先按 `Author.id` 查找，再按 `Author.url_token` 查找；解析结果同时包含稳定 `authorId`、规范 `urlToken` 和去重后的兼容别名集合。
3. `Author.id` 是持久化、关系关联和内部查询的首选身份。已有表同时保存 `author_id` 与 `author_url_token` 时，查询优先稳定 ID，并兼容当前任务输入与数据库已有 token 数据。
4. `Activity` 表目前没有 `author_id`，本期不扩展数据库 schema；活动查询使用已解析的规范 token，并兼容任务输入与稳定 ID 别名。该边界不得影响本次及现有数据库生成。
5. 作者分页抓取在首次取得作者信息后，普通用户任务统一使用响应中的规范 `url_token` 继续请求和写入关系；用户提问关系不得再把原始 hash 写入 `author_url_token`。
6. 生成书名、运行诊断和 HTML/Markdown/EPUB 内的用户主页链接统一使用规范 `url_token`；若响应确实没有 token，才回退稳定 `id`。链接统一使用 HTTPS。
7. 本次兼容现有 SQLite，不重建或清空业务数据库。已有 `Author`、`Answer`、`Article`、`Pin` 与 `Author_Ask_Question` 数据应可直接生成。
8. 销号用户任务继续保留其专用抓取行为；能由返回的稳定 ID 或 token 解析时复用同一生成流程，不把统一的“已注销账号”模板 token 当成原始任务的请求地址。

## 实现范围

- 新增共享的作者身份字段归一化工具和模型 resolver。
- 修正全部用户型生成任务对作者、回答、文章、想法、提问关系和活动的查询参数。
- 修正普通用户批量抓取器在 hash 与规范 token 不同时的分页、关系持久化和后续查询。
- 修正 GUI 默认任务标题、作者书名及回答、文章、想法模板中的主页链接展示。
- 同步更新开发文档中的用户身份、数据库关系与抓取/生成流程说明。

## 验收

1. 隔离 SQLite 中写入 `Author(id=legacy-hash, url_token=canonical-token)` 后，用两种标识都能解析为同一用户，未知标识仍返回空。
2. 离线集成测试真实贯通“hash 任务输入 → 作者接口返回不同 token → Author/Answer 持久化 → GenerateWorkflow 组装”，不得 mock 掉持久化。
3. 普通 canonical token 输入保持兼容；用户型任务共享同一 resolver。
4. 关系查询能读取稳定 `author_id` 数据，并兼容按当前 token 或原任务标识保存的旧记录；本期不承诺解析未持久化的失效历史 token。
5. 生成书名和作者主页链接包含规范 token，不包含仅供内部关联的 hash；token 缺失时有稳定 ID 回退。
6. 不存在的用户仍给出明确的缺失实体诊断；不可恢复数据库错误不得被当作空结果。
7. 通过类型检查、单元测试、本地集成测试、前后端构建和 Electron 人工冒烟；不得读取或覆盖测试沙箱外的业务数据。
