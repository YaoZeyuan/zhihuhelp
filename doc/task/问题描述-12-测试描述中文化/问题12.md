# 问题 12：测试描述中文化

## 状态

需求信息已经齐全，可以启动全量开发。

## 背景

`tests/unit`、`tests/client` 与 `tests/integration` 中的大部分 Vitest 测试描述为英文，不利于通过终端输出快速定位失败场景。本次统一改为中文描述，并保留必要的技术名词和精确标识。

## 需求

1. 中文化三个测试目录内全部 `describe`、`it`、`test` 及其 `.each` 参数化标题。
2. 只用于测试标题插值的 `label` 同步中文化；参与断言或业务逻辑的值保持不变，必要时新增独立的中文标题字段。
3. 保留 `IPC`、`HTTP`、`JSONL`、`SQLite`、`HTML`、`Markdown`、`EPUB`、`Electron`、`Worker`、`CommonJS`、`ESM`、`partial_success`、`url_token`、类名、字段名等必要专业名词。
4. 保留 `%s`、`%#`、`$label` 等参数占位符，保证参数化展开后的标题仍可区分场景。
5. 不修改测试文件名、Vitest project 名、断言消息、mock 数据、fixture、快照或生产代码。
6. 新增 AST 级测试标题检查命令，并接入全部离线测试命令，阻止后续新增纯英文人类可读标题。
7. 更新测试开发文档，说明中文描述规范、保留术语和检查命令。

## 验收

1. `pnpm test:titles` 扫描三个目录，所有测试标题至少包含一个汉字；失败时输出文件、行号和标题。
2. 检查器覆盖直接调用、`.each`、多行与模板标题，并有临时 fixture 测试验证中文通过、纯英文拒绝和占位符保留。
3. 三个 Vitest project 的展开标题均为中文语义，且参数值仍可用于定位。
4. `pnpm tsc` 与完整 `pnpm test` 通过。
5. Prettier 与 `git diff --check` 通过，业务行为保持不变。

## 已接受边界

- Vitest project 名 `unit`、`client`、`integration` 保持不变。
- 个人保存的 `vitest -t "旧英文标题"` 命令需要改用新的中文标题。
- 本次不涉及生产构建。
