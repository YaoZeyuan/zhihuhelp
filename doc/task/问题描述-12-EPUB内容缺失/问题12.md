# 问题 12：EPUB 内容缺失

## 问题

Windows + Node.js 24 环境中，`adm-zip` 的 `addLocalFolderPromise()` 无法读取目录，并把 `fs.open(directory)` 的错误错误地当作成功结果。生成流程因此只把 `mimetype` 写入 EPUB，最终文件约 134 字节，但仍被报告为成功。

HTML、OPF、TOC、CSS 和图片已经正确写入 EPUB 缓存目录，问题仅发生在 ZIP 打包阶段。

## 需求

1. 不再使用 `adm-zip` 的异步目录导入；由项目代码确定性遍历 `META-INF` 和 `OEBPS`，逐文件加入 ZIP。
2. `mimetype` 必须继续作为第一个、未压缩的 ZIP 条目。
3. 写出前验证 EPUB 至少包含 `META-INF/container.xml`、`OEBPS/content.opf`、`OEBPS/toc.xhtml` 和一个 `OEBPS/html/*.html` 正文；缺失时生成失败，不得记录成功或复制残缺文件。
4. 测试必须打开真实 EPUB，验证必需条目、正文内容、OPF manifest/spine 引用和合理文件大小；完整 workflow 测试不能只断言扩展名存在。
5. 测试继续使用隔离目录，不读取或覆盖现有业务缓存和输出。

## 验收

- 实际生成的 EPUB 不再只有 `mimetype`，正文 HTML 与静态资源进入压缩包。
- EPUB 首条目符合规范，OPF 中引用的正文均能在 ZIP 中找到。
- 单卷、双卷 fixture workflow 均验证每个 EPUB 的内部结构。
