## 需求 3：VitePress 文档站

### 状态

需求信息已经齐全；VitePress 文档站、Mermaid 放大交互、首页品牌宣传图调整和根 `api` 发布镜像已完成实现和验收。

### 站点定位与发布

- 使用实施时可获取的最新 `VitePress 2.0 alpha`，不退回 VitePress 1.x。
- 新站同时承担产品官网和项目文档职责，整体替换旧官网，正式地址为 `https://zhihuhelp.yaozeyuan.online/`。
- 用户指南使用 `/guide/` 路由，开发文档使用 `/dev/` 路由；站内链接使用稳定英文路径，不暴露中文文件名编码路径。
- 旧 `homepage` 分支及其部署流程不再承担官网发布职责。新的 GitHub Actions 从 `master` 构建并发布 VitePress，支持 `master` 推送和手动触发。
- 发布产物包含自定义域名配置，不提交本地构建目录。仓库设置中的 GitHub Pages 发布源需要与新工作流保持一致。
- 仓库根 `api` 是文档站的公开静态数据目录。每次 `pnpm docs:build` 必须在 VitePress 成功后将它完整复制为发布根目录的 `/api/**`，保持文件名、目录层级和内容不变；当前版本接口发布为 `/api/zhihuhelp/version`。

### 文档目录与公开边界

- 除仓库根 `README.md` 外，面向站点的项目文档统一收拢在 `doc` 目录。
- 当前用户文档迁入 `doc/guide`，当前开发文档迁入 `doc/dev`；正文只维护一份，VitePress 直接使用这些 Markdown 作为内容源。
- `doc/task` 是需求处理记录，`doc/项目文档` 是历史设计资料，两者继续留在仓库中，但必须从站点构建、导航、搜索、站点地图和页面索引中排除。
- fixture、日志、本地配置、测试产物及组件内部 README 不属于公开站点内容。
- 除明确公开的根 `api/**` 外，不得把 `src/api`、后端源码、`config.json`、Cookie 或数据库复制到站点产物。构建校验必须比较根 `api` 与发布目录的文件集合和内容，并继续对公开 API 文件执行敏感信息扫描。
- 新增产品首页和项目元信息页面，提供 GitHub、GitHub Releases、MIT 许可证、问题反馈和贡献入口。本期不调整安装包发布流程。

### 信息架构与功能

- 顶部导航包含：首页、用户指南、开发文档、GitHub。
- 用户指南包含：快速开始、功能说明、数据浏览与输出结果、常见问题。
- 开发文档包含：开发环境与命令、架构总览、业务流程、前端/Electron/后端分工、数据与日志、测试与 Fixture、维护注意事项。
- 首页展示项目定位、支持的知乎内容类型、任务执行流程、HTML/EPUB 输出、数据浏览、运行诊断，以及用户文档和开发文档入口。
- 提供中文界面、本地全文搜索、浅色/深色主题、移动端导航、页内目录、上一篇/下一篇、最后更新时间、GitHub 编辑入口、站点地图和 Mermaid 流程图渲染。
- 每张 Mermaid 流程图提供键盘可访问的放大查看入口；优先在当前页面全屏展示，并支持关闭与 `Esc` 退出。浏览器不支持或拒绝全屏时，回退为在新标签页打开独立 SVG。
- 首版不做博客、多语言、评论、服务端搜索或 CMS。
