# 问题 14：运行日志、任务管理与输出目录调整

## 状态

需求信息已经齐全，可以启动全量开发。

## 一、本 GUI 会话错误列表

### 现状

“运行日志”当前从持久化日志中展示一个“最近错误”。软件重启、页面刷新或窗口重开后，上一会话的错误仍会出现，容易让用户误以为问题仍在发生。

### 最终需求

1. 将单条“最近错误”改为“本会话错误”列表。
2. 本会话以 renderer 文档启动时间为起点：
   - 刷新页面或重开窗口会开始新会话，旧错误不再展示。
   - 普通标签切换、自动刷新日志和手动刷新日志不会重置会话。
3. 只读取后端 `runtime.*.jsonl`，不合并 `frontend.runtime.*.jsonl`，不新增前端日志读取 IPC。
4. `level=error` 或 `status=failure` 的事件进入错误列表；`partial_success` 和普通 warning 不进入错误列表。
5. 每个结构化错误事件平铺展示，按时间倒序排列；stage、workflow、IPC 等不同层级的 failure 不合并。
6. 错误项至少展示发生时间、阶段或 `eventCode`、消息以及结构化错误内容；没有本会话错误时展示明确空状态。
7. 清空日志继续清理现有持久化日志，并立即清空当前会话错误列表；该功能不改变日志文件的五日保留规则。

## 二、任务管理调整

### 2.1 全局“跳过抓取”

1. 在“高级配置”中新增全局“跳过抓取” Switch。
2. Switch 由现有任务的 `skipFetch` 聚合得出，不新增 `skipAllFetch` 等第二份配置字段，不修改后端 schema 或 IPC：
   - 所有现有任务均跳过抓取时，Switch 开启。
   - 任意任务启用抓取时，Switch 关闭。
3. 打开 Switch 时，所有现有任务都改为跳过抓取；直接关闭 Switch 时，所有现有任务都恢复抓取。
4. Switch 开启期间，通过快捷识别或批量编辑新增的任务继续继承“跳过抓取”。
5. 任意一行重新勾选抓取后，Switch 自动关闭；逐行取消最后一个仍启用的抓取任务后，Switch 自动开启。
6. 父表单批量修改 `skipFetch` 后，每一行的抓取 Checkbox 必须立即同步，不能出现表单值和界面状态不一致。

### 2.2 链接自动识别

1. 快捷输入内容由用户修改后自动识别，无需必须点击“识别链接”。配置初始化写入输入框时不得触发自动识别，避免覆盖已加载任务的备注和抓取配置。
2. 使用 lodash `throttle`，间隔 1000ms，同时启用 leading 与 trailing：
   - 第一次输入立即识别。
   - 连续输入期间最多每秒识别一次。
   - 最后一次输入内容必须最终完成识别。
3. 保留“识别链接”按钮作为立即执行入口；点击按钮前取消尚未执行的 trailing 调用，避免之后重复覆盖。
4. 组件卸载时取消待执行的节流调用。
5. 自动识别继续沿用现有“按输入内容整表替换”的规则：不追加、不去重，保持输入顺序，保留重复项与无法识别的非空行。
6. 清空快捷输入时同步清空旧识别结果且不弹 warning；手动点击按钮时输入为空，继续保留现有提示。
7. 自动识别不新增成功或失败 toast，继续使用现有任务数量摘要和无效链接 Alert 展示结果。

## 三、输出目录与输出历史

### 3.1 新输出目录

最终输出改为按安全书名聚合，再按格式拆分：

```text
知乎助手输出的电子书/
├─ <安全书名>/
│  ├─ html/**
│  ├─ markdown/**
│  └─ epub/<安全书名>.epub
├─ json/**
└─ diagnostics/**
```

具体要求：

1. HTML 输出目录为 `<输出根>/<安全书名>/html`。
2. Markdown 输出目录为 `<输出根>/<安全书名>/markdown`。
3. EPUB 文件为 `<输出根>/<安全书名>/epub/<安全书名>.epub`。
4. 缓存仍保持 `缓存文件/{html|markdown|epub}/<安全书名>` 的现有结构，不随最终输出目录迁移。
5. `html`、`markdown`、`epub`、`json`、`diagnostics` 是输出根下的保留书名；发生冲突时必须生成安全且稳定的替代目录名。
6. 同名书重新生成时，只清理和重建该书的输出根，不得影响其他书、JSON 导出或诊断文件。
7. 全局“打开电子书输出目录”继续打开总输出根。

### 3.2 输出日志与历史

1. 每本书的 `output.created` 必须记录书籍级 `outputPath=<输出根>/<安全书名>`；HTML、Markdown、EPUB 的精确路径继续保留在结构化日志中用于诊断。
2. 输出历史只接收具有书籍级 `outputPath` 的新记录，并按该路径去重、倒序展示。
3. 每条输出历史只显示一个“打开文件夹”按钮，打开书籍级 `outputPath`；不再分别显示“打开 HTML”“打开 Markdown”“打开 EPUB”。
4. 不迁移、不删除旧布局中的文件；项目更新后旧目录由发布/更新流程统一删除，本功能不承担迁移职责。
5. 不为最近五日旧日志增加 HTML、Markdown、EPUB 路径回退。旧记录没有书籍级 `outputPath` 时不进入新输出历史，并随日志保留周期自然淘汰。
6. 局部成功的输出只要书籍级目录存在，仍保留历史项和警告状态，用户可以从统一文件夹查看实际产物。

## 验收要求

1. 页面启动前的后端错误不出现在“本会话错误”中；页面启动后的多个错误按倒序展示；刷新页面后列表清空。
2. 全局 Switch 与每行抓取 Checkbox 双向联动，配置往返仍只使用逐任务 `skipFetch`。
3. 快捷输入首次修改立即识别，连续修改不超过每秒一次，最后值必定生效；初始化、手动按钮、清空和卸载场景均不会产生延迟覆盖。
4. 新生成的每一本书都只有一个书籍级目录，其下包含 `html`、`markdown`、`epub`；多卷和同名重跑不会互相覆盖或越过输出根。
5. 输出历史只显示一个“打开文件夹”按钮；旧日志没有 `outputPath` 时不显示对应历史。
6. 更新前端组件、路径与生成逻辑、结构化日志、docs preview、相关单元/组件/集成测试，以及 `doc/guide`、`doc/dev` 中受影响的流程和目录说明。
