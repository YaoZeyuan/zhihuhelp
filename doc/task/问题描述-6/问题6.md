### 在线采集 fixture 的可行方案

可以做，并建议采用显式更新、人工审阅的方式，而不是让普通测试自动刷新：

1. `pnpm fixtures:refresh` 是唯一允许联网并更新 fixture 的命令。
2. 命令只读仓库根目录 `config.json` 中的 `request.cookie`，不得复制、打印或写入测试产物。
3. 采集时只请求场景清单所需的最少页数；保存前递归脱敏，并裁剪为测试真正使用的字段。
4. 每份 fixture 带 `schemaVersion`、`sourceType`、`capturedAt` 和内容校验值，但不保存 Cookie、完整请求头或私人数据。
5. 更新结果必须先通过 schema 校验和离线测试，再由人工检查 diff 后提交。
6. `pnpm test` 永不联网、永不自动更新 fixture；fixture 过旧只给出维护提示，不导致离线测试随机失败。

当前请求签名依赖 Electron 内的 js-rpc bridge，普通 Node 测试进程不能直接完成真实知乎请求。

@todo(worker) 请确认允许 `pnpm fixtures:refresh` 和 `pnpm test:online` 启动一个隐藏的 Electron/js-rpc 签名运行时。它只提供签名和请求能力，不操作 UI，因此不计入本期排除的“真实 Electron UI E2E”。这是保持现有签名逻辑、避免大范围重写的推荐方案。
